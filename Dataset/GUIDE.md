## 0. The one thing to get right first

This data is **simulated**. It was generated by a causal model, not collected from human
participants.

Label it as simulated in the report, on the dashboard, and in the viva. Every file already says
so — there is a `data_source` column set to `SIMULATED` on all 3,000 rows, and the README sheet
of the workbook leads with it.

This is not a weakness in the project. It is a legitimate and common engineering strategy:
validate the software pipeline independently of hardware availability, then swap the simulated
input for the real sensor feed. Presenting it as real collected data, on the other hand, is
research misconduct. The difference between those two positions is one sentence in the report.

**Say this:**

> The current prototype uses a simulated physiological data interface so that the complete ML
> and software pipeline can be validated independently of sensor availability. The system
> architecture is hardware-ready; MAX30102 / ESP32-C3 integration is the planned acquisition
> layer for the next phase.

## 2. How the data is structured

### One row = one question/answer trial

```
300 participants × 10 trials = 3,000 rows
Each participant: 5 truthful + 5 deceptive
```

Not one row per person. Within-person variation is what makes the experiment work — you compare
a participant against their own baseline, not against a population average.

### Why the columns correlate instead of being random noise

Every row came out of a causal chain:

```
  participant traits            question difficulty        condition (truth/lie)
  (anxiety, deception skill,           +                          +
   resting HR, speech rate,                                  habituation
   blink rate)                                            (trial 10 < trial 2)
              │                        │                          │
              └────────────────────────┼──────────────────────────┘
                                       ▼
                      latent AROUSAL  +  latent COGNITIVE LOAD
                                       │
              ┌────────────────────────┼────────────────────────┐
              ▼                        ▼                        ▼
      physiological channel      audio channel            vision channel
       (own noise term)          (own noise term)         (own noise term)
              │                        │                        │
              ▼                        ▼                        ▼
        HR / HRV / SpO2 /      latency / pauses /        blink / gaze /
        perfusion index        pitch / jitter            head pose / AUs
              │                        │                        │
              └────────────────────────┼────────────────────────┘
                                       ▼
              signal quality (room noise, lighting, motion, perfusion)
              ATTENUATES the signal and adds measurement noise
```

Things you can verify in the data, and should mention:

- Caffeine and poor sleep raise resting HR, which raises every HR reading for that participant.
- Anxious participants look aroused even when telling the truth. That is why per-trial baselines
  exist, and why `heart_rate_change_from_baseline` beats raw `heart_rate_bpm`.
- Participants high in deception skill leak less, so some deceptive trials look entirely normal.
- Arousal habituates: trial 10 is calmer than trial 2 under the same condition.
- Derived columns are arithmetic, not independent draws. `heart_rate_change_from_baseline` is
  exactly `heart_rate_bpm` minus `baseline_heart_rate_bpm`. `pause_ratio` is exactly silence over
  duration. The seven expression probabilities sum to 1.0 in every row.

**Read this as an engineering priority list.** Hesitation and timing carry the signal. SpO₂

The last four rows are the whole argument for baseline-relative measurement in one table. The
*same eyebrow*, measured four ways: the delta from the person's own baseline carries real signal
(0.30); the absolute distance carries almost none (0.07); the resting anatomy carries exactly none
(0.00, as it should — brow shape has nothing to do with lying); and the version measured in raw
camera pixels is worse than useless (−0.08).

## 3b. The computer-vision features, and how the eyebrow measurement works

The dataset now carries 52 additional CV columns covering eyebrow geometry, head-pose baselines
and deltas, per-eye openness, gaze deltas, and whole-face temporal motion. Here is what they mean
and why they are shaped the way they are.

### You do not train OpenCV on the CSV

Keep these two things separate:

```
OpenCV + MediaPipe  →  extracts numbers from video   (per frame)
scikit-learn        →  learns from those numbers     (one row per trial)
```

OpenCV handles camera capture and image processing. MediaPipe Face Mesh gives you the 468
landmarks. Neither of them "detects lying" — they produce measurements. The ML model learns from
the measurements.

### 600 frames become one row

A 20-second answer at 30 fps is 600 frames. You do not want 600 rows.

```
600 frames of landmarks
        ↓
per-frame measurements (brow-eye distance, EAR, head angles, gaze)
        ↓
aggregate over the window: mean, std, peak, delta, velocity, event count
        ↓
ONE feature vector  →  ONE row in the CSV
```

That is exactly the shape of this dataset. `eyebrow_raise_event_count = 3` means three discrete
raises were detected across the window; `left_eyebrow_movement_std` is the variability across
frames.

### How a slight eyebrow raise is detected

Not by absolute position. By distance from brow to eye, divided by inter-ocular distance:

```
        ●  ●  ●  ●  ●     ← brow landmarks
             │
             │  brow_eye_distance
             │
        ○         ○        ← eye centres
        └────┬────┘
        inter-ocular distance   (the normaliser)
```

`brow_eye_distance / inter_ocular_distance` — that ratio is the measurement.

Dividing by inter-ocular distance is what makes it scale-free. Lean toward the webcam and both
distances grow together, so the ratio does not move. Without that division, leaning forward
registers as an eyebrow raise.

Then compare against the person's own baseline:

```
baseline window (pre-question)  →  0.4210
answer window                   →  0.4335
delta                           →  +0.0125
```

Person A may sit at 0.38 and Person B at 0.47 purely from anatomy. The model must never learn
that Person B is more deceptive. That is why `left_eyebrow_height_delta` is the feature and
`left_eyebrow_eye_distance` is not.

### Head pose, and the confound left in on purpose

Tilt your head back and your eyebrows rise in the camera image without a single muscle moving.
This is the trap, and the dataset contains a worked demonstration of it.

| Column | What it is |
|---|---|
| `left_eyebrow_height_delta` | Measured in the face coordinate system. Correct. |
| `naive_left_eyebrow_delta_camera_frame` | Measured in raw camera pixels. **Deliberately flawed.** |

From `mosaic_recompute_stats.py`:

```
d(left_eyebrow_height_delta)                = +0.296
d(naive_left_eyebrow_delta_camera_frame)    = -0.081   ← signal gone, sign flipped

face-relative brow delta vs AU01 (brow raiser):  r = +0.650
raw-camera brow delta vs head pitch:             r = +0.918   ← measuring head, not brow
face-relative brow delta vs head pitch:          r = -0.169
```

The naive column correlates 0.92 with head pitch. It is a head-movement detector wearing an
eyebrow costume.

And the `Headpose_Check` sheet shows what that costs:

| Features | Accuracy | AUC |
|---|---|---|
| Eyebrow only — face-relative | 0.570 | 0.604 |
| Eyebrow only — raw camera frame | 0.505 | 0.517 |
| Full vision set — face-relative brow | 0.683 | 0.744 |
| Full vision set — raw camera brow | 0.682 | 0.744 |

Two lessons, both worth writing up:

1. **On its own, the badly-measured feature is worthless** — 0.517 AUC is a coin flip.
2. **Inside a rich feature set the difference nearly vanishes**, because head pose is also in the
   feature set and the model learns to subtract it. A good feature set can *hide* a badly measured
   feature rather than fix it. Measure it properly anyway — you will not always have 59 other
   features to cover for you.

`naive_*` columns are excluded from every model feature set. They exist for the report.

### Why the eyebrow features agree with the Action Units

AU01 (inner brow raiser) and AU02 (outer brow raiser) *are* the eyebrow raise in FACS terms. The
geometric measurement is derived from them, so the two agree by construction — r = 0.65 between
`left_eyebrow_height_delta` and `au01_intensity`. If you ever compute both from real video and
they disagree, one of your two extractors is broken.

### What is deliberately NOT in the dataset

The 468 raw landmark x/y/z coordinates — that would be 1,404 columns of mostly noise. Store them
only if you later train a sequence model (LSTM/temporal CNN) on frame-by-frame data. For the
current architecture, derived movement features are the right abstraction.

### One caution for the report

`looking_away_ratio`, `gaze_deviation_degrees` and the blink features are **behavioural
observations, not deception indicators**. Averting your gaze under questioning is normal. These
are inputs to a model, and the model's output is a probability under an experimental protocol —
not a verdict. Say this in the limitations section before anyone says it to you.

## 4. Three rules you cannot break

### Split by participant, never by row

```python
from sklearn.model_selection import GroupKFold

for train, test in GroupKFold(n_splits=5).split(X, y, groups=df.participant_id):
    ...
```

All 10 trials of one person must land in the same fold. Otherwise the model memorises that
person's baseline from their training trials and recognises them in the test set. Your accuracy
goes up and it means nothing. Every probability column in this dataset was produced this way.

### Never train on these columns

| Column | Why |
|---|---|
| `ground_truth_binary`, `ground_truth_label` | The target |
| `experiment_condition`, `deception_instruction` | Aliases of the target |
| `*_model_probability`, `*_model_prediction` | Model outputs, not inputs |
| `prediction_confidence`, `prediction_correct` | Evaluation only |
| `question_id`, `question_difficulty` | See section 5 |

### Don't call it a lie detector

Call it **multimodal deception analysis** producing an **experimental classification**. The
system measures physiological, speech and facial-behavioural correlates of arousal and cognitive
load. Those correlate with deception; they are not proof of it. Stress, anxiety, fatigue, and
being questioned by a stranger all produce the same signals.

This wording is not academic politeness. It is what makes the ethics and limitations sections
defensible.

## 5. The confound that was found and fixed

The first version of this dataset had a flaw worth understanding, because it is the single most
likely thing an examiner will probe.

**The problem:** deceptive trials were drawn from the hard probe questions ("Did you take the
blue file?") and truthful trials from easy control questions ("Is the room light on?"). Question
difficulty separated the classes with Cohen's d = 1.19. A model could score well by recognising
*which question was asked* — learning nothing about deception at all.

**The fix:** condition is now assigned to questions at random, per participant. The same question
appears as truthful for one participant and deceptive for another.

**The residual:** Q01 is always truthful, because a known-true question first is how you establish
a resting baseline. That leaves a small imbalance, d ≈ 0.26. For that reason `question_id` and
`question_difficulty` are excluded from every model feature set.

Put this in the report. Finding and correcting your own confound is a stronger result than never
having had one.

## 6. The numbers, and why they are not higher

| Model | Accuracy | F1 | ROC-AUC |
|---|---|---|---|
| Physiological | 0.624 | 0.626 | 0.667 |
| Audio | 0.703 | 0.698 | 0.768 |
| Computer vision | 0.683 | 0.685 | 0.744 |
| **Late fusion** | **0.738** | **0.736** | **0.806** |

Ablation, from the `Ablation` sheet:

| Combination | Accuracy | ROC-AUC |
|---|---|---|
| Physiology | 0.624 | 0.667 |
| Audio | 0.703 | 0.768 |
| Vision | 0.683 | 0.744 |
| Physiology + Audio | 0.708 | 0.774 |
| Physiology + Vision | 0.683 | 0.755 |
| Audio + Vision | 0.729 | 0.805 |
| All three | 0.724 | 0.806 |

Two honest findings to report rather than hide:

1. **Fusion beats every single modality** — 0.726 against a best-single 0.680. That is the
   project's core claim, demonstrated.
2. **Physiology adds nothing on top of audio + vision** (0.724 vs 0.729). Report it. Investigating
   why is a genuine discussion section: the oximeter channel is noisy, arousal is slow relative to
   a 30-second trial, and the audio channel already captures much of the same arousal.

**Why 74% and not 95%.** Untrained humans detect deception at roughly 54% — barely above a coin
flip. Published multimodal systems land at 65–75%. A 95% result on this problem would mean the
dataset was broken, not that the model was good. Near-perfect accuracy is the fastest way to have
a synthetic dataset questioned.

## 7. Deliberate imperfections — do not "fix" these

| Property | Why it is there |
|---|---|
| Classes overlap heavily | Real behaviour overlaps. Clean separation is the signature of fake data |
| SpO₂ is a weak predictor | It genuinely is. Tuning it up would be inventing physiology |
| ~5% of trials missing a whole modality | Sensors drop out. `*_available` flags mark them |
| Some trials flagged `POOR` quality | Tests the review path. They should not be scored silently |
| Some deceptive trials look completely normal | High deception-skill participants. Real, and the reason ceiling accuracy is impossible |

## 9. Viva questions, with answers

**"Is this real data?"**
No. It is simulated, and every file states so, including a `data_source` column on all 3,000
rows. It was generated to validate the software and ML pipeline independently of hardware
availability. The schema matches what the MAX30102 and the audio and vision pipelines will
produce, so real data drops into the same code path.

**"Why is the accuracy only 74%?"**
Deception detection is genuinely hard. Untrained humans are near chance; published multimodal
systems reach 65–75%. A higher number would indicate a broken dataset rather than a better model.

**"Couldn't the model just be recognising which question was asked?"**
No. Condition is counterbalanced across questions — the same question is truthful for one
participant and deceptive for another — and `question_id` and `question_difficulty` are excluded
from every feature set. This was a real confound in the first version, measured at d = 1.19, and
it was found and corrected.

**"How do you know there is no data leakage?"**
Participant-level GroupKFold. All ten trials of a participant stay in one fold, so the model
cannot memorise an individual's baseline. `mosaic_recompute_stats.py` reports the row-split score
alongside the participant-split score so the two can be compared directly.

**"Why does SpO₂ barely contribute?"**
Because blood oxygen is not meaningfully modulated by the stress of answering a question. It is
retained as one input among many, and its weakness is reported rather than hidden. This matches
the physiology literature.

**"What happens when the hardware is connected?"**
The acquisition layer is replaced; nothing downstream changes. Feature extraction, the models,
and the dashboard all consume the same schema.

## 10. Regenerating or changing the dataset

```bash
python mosaic_generate.py    # traits, latents, features -> _stage1.csv
python mosaic_models.py      # trains models, writes probabilities -> _stage2.csv
python mosaic_build.py       # CSVs + workbook
```

Run them in that order; each depends on the previous. The random seed is `20260811`, so the
output is identical every time unless you change the seed.

Useful knobs in `mosaic_generate.py`:

| Variable | Effect |
|---|---|
| `N_PARTICIPANTS` | Number of participants |
| `1.15 * cond` in `arousal` | Raise for a stronger physiological/visual signal |
| `0.90 * cond` in `cog_load` | Raise for a stronger speech-hesitation signal |
| `QUESTION_BANK` | Add or edit questions |
| Dropout rates in section 11 | How often a modality goes missing |

If you raise the effect sizes, re-check the accuracy afterwards. Anything above roughly 85%
starts to look implausible for this problem, and you will be asked about it.
